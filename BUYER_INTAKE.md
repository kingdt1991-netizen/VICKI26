# Black Knight Technology — Buyer Intake

You do not need to know which product you need. Start with the outcome.

## 1. What are you trying to accomplish?

Choose the closest lane:

- **Launch software safely** — commercialization, readiness, rights, release risk.
- **Verify work or evidence** — claims, provenance, evidence packages, decision trails.
- **Check APIs or releases** — endpoint health, configuration, artifacts, CI/CD or release preflight.
- **Assure an AI agent/workflow** — bounded execution, agent assurance, machine-readable verification.
- **Automate governed commerce** — enterprise A.C.E. evaluation/licensing.
- **Not sure** — describe the business outcome in plain language.

## 2. Safe information to provide

- public website or repository URL;
- high-level problem description;
- desired deliverable;
- public technical context;
- deadline or urgency;
- whether you prefer a fixed-price product, pay-per-use machine service, or enterprise discussion.

## 3. Do not post publicly

Do **not** put credentials, private keys, API secrets, customer-confidential information, wallet signing material, private database strings, unpublished proprietary source, Crown IP, or sensitive evidence in a GitHub issue.

If a product requires private intake, the public step should contain only enough information to route you to the approved secure intake path.

## 4. Routing

| Need | Likely route |
|---|---|
| Commercial software readiness | RightsGate / Launch Readiness |
| Evidence, claim, provenance or decision verification | ProofForge / Evidence Assurance |
| API/configuration/release checks | QuickScan + TaskForge / API Reliability |
| AI-agent/workflow assurance | TaskForge + ProofForge / Agent Assurance |
| Governed autonomous commerce | A.C.E. / Commerce Readiness |
